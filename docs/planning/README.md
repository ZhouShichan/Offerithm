## 后续建议

本批核心闭环之后，继续核验政策来源与年度，明确预测/评分口径，再推进高级薪资和政策编辑入口。继续保留浏览器本地运行、函数式计算核心和静态部署；当前没有引入登录、后端或自动云同步的需求依据。

“模型已有”不等于用户可用，“建议”也不等于已经确认的业务需求。尤其是政策、税务、储蓄及预测口径，需要明确适用年度和来源后才能形成最终验收样例。

## 原分析中的待办

此表保留原排序及动机；0A/0B/0D/0E 的本地修复见 04，P1 共享校验、基础成本/工时、草稿与导入闭环见 05。政策核验及真实发布验收仍单独待办。

| 顺序 | 待办 | 为什么现在做 |
| --- | --- | --- |
| 先修正 | 非月度现金漏计、比较得分错列、生产子路径路由 | 会影响金额、决策归属或页面可用性 |
| 先加固 | 运行时输入校验、IndexedDB提交反馈、JSON批量原子导入 | 避免错误数据和“提示失败但部分已写入”的不一致 |
| 核心补齐 | 生活成本/工时输入、草稿恢复、结果假设说明 | 目前默认值或缺少入口，用户无法完成完整决策流程 |
| 再完善 | 多频率薪资/阶梯奖金、政策与扣除配置、可解释评分 | 底层已有部分能力，需要明确口径后接入界面 |
| 待确认 | CSV导入、多命名工作区、逐月预扣、自动择优税法 | 现有代码不能证明这些是已批准的后续需求 |
