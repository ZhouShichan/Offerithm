## 1. 测试目标与范围

测试的首要目标是确认用户看到的薪酬估算**数值口径正确、来源透明、正式数据不会被草稿或导入操作无意覆盖**。测试依据以 PRD 的用户可观察行为为准，计算与存储接口约定参照 Tech Design。

### 1.1 MVP 测试范围

本轮发布验证覆盖：

1. 快速估算的三类基础输入、默认假设与解释性展示（PRD-M01）。
2. 保存正式 Offer 和基础工作区比较（PRD-M02）。
3. 薪资组成、奖金规则、总包对账与重复计入防护（PRD-M03）。
4. 五险一金、政策匹配／回退、年度个税及年终奖两种计税口径（PRD-M04）。
5. 补贴、生活成本、双储蓄口径与权益隔离（PRD-M05）。
6. 基础加权排序、指标解释与数据状态展示（PRD-M06）。
7. XLSX 多工作表全量导入、导出、冲突预览和 schema 校验（PRD-M07）。

### 1.2 非 MVP 与待排期场景

`Scenario`、三档情景、3／10 年预测、帕累托、敏感度／排名稳定性、全局偏好模板版本同步、政府补贴条目、CSV 报表导出**不进入 MVP 阻断性验收**。高级草稿批量流程、撤销／重做、有效时薪、完整地理成本及 JSON 备份／恢复虽已记录产品规则，发布批次未逐项锁定；仅在对应功能实际纳入迭代时增加其专项测试。

**注意**：技术设计预留了模型字段或工作表名称，不足以证明该功能需要在本次 MVP 中通过测试。

## 2. 测试原则与分层

| 层次             | 关注点                                                       | 主要验证接缝                                  |
| ---------------- | ------------------------------------------------------------ | --------------------------------------------- |
| 纯函数单元测试   | 固定输入下的薪资、社保、个税、储蓄、权重排序结果             | `calculateOffer` 及薪资、保险、税务、比较模块 |
| 仓储行为测试     | 正式保存、草稿保留、跨记录引用和事务失败                     | 仓储封装及 IndexedDB 测试环境                 |
| 数据交换契约测试 | XLSX 工作表 ↔ 领域对象双向映射、schema、错误定位、关联完整性 | 导出／导入解析与验证边界                      |
| 界面／端到端测试 | 首次输入、解释标签、可见 warning、保存确认、导入冲突确认     | 用户能观察到的交互结果                        |

- 测试**外部可观察结果与不变量**，不把函数拆分方式、状态变量名、DOM 内部结构或组件实现细节当成业务断言。
- 对金额类计算使用**明确城市、年度、政策版本和输入口径的固定夹具**；期望值应由经核验的政策文本与独立人工推导得出，不能简单复用被测实现的计算结果生成快照。
- 测试必须区分：输入确实为 `0`、输入未知、采用系统样例、来自已确认事实。对未知值不允许自动断言为真实零值。
- 可通过组合少量端到端冒烟和大量纯函数断言降低 UI 重构造成的测试脆弱性。

## 4. MVP 重点验收用例

以下为**测试意图与预期行为**，非已执行结果。所有断言中的具体金额应以经核验的测试夹具填入；本次三份资料没有提供可直接引用的完整官方税率／地方社保测试样本。

### 4.1 快速估算与状态

| 编号      | 前置条件／操作                                               | 预期行为                                                                                                    |
| --------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| **TP-01** | 新用户进入应用，仅输入城市、企业类型和一种薪资方式           | 不要求注册；可看到年度税后现金、两种储蓄估算与必要默认假设                                                  |
| **TP-02** | 同一 Offer 分别以年薪总包、月薪×月数、自定义结构录入等价报价 | 等价已知输入在相同假设下得到一致结果；切换输入方式不会将总包和明细相加                                      |
| **TP-03** | 省略一个关键政策输入，或只使用系统生活成本样例               | 展示 `unknown`／`system-estimate`／`policy-default` 对应信息；不误显示为 `confirmed`；真实 0 与缺失能够区分 |
| **TP-04** | 从估算页显式「保存为 Offer」                                 | 生成正式 Offer；首次保存有默认工作区；工作区引用的是同一正式记录                                            |
| **TP-05** | 模拟正式 Offer 保存失败（例如写事务失败）                    | 不提示保存成功；原正式记录不被部分覆盖；仍可恢复未提交内容（该草稿流按实际交付范围验证）                    |

### 4.2 薪资组成和对账

| 编号      | 前置条件／操作                                 | 预期行为                                                           |
| --------- | ---------------------------------------------- | ------------------------------------------------------------------ |
| **TP-06** | 同时提供总包与明细，且合计不一致               | 展示差额与警告；用户明确选择对账依据后计算；不得把总包再加到明细上 |
| **TP-07** | 提供固定奖金、绩效系数奖金及阶梯奖金的边界输入 | 三种已支持规则按各自定义得到正确金额；在阶梯档位边界无重复或漏计   |

### 4.3 社保、公积金与个人所得税

| 编号      | 前置条件／操作                                                                     | 预期行为                                                                                    |
| --------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **TP-09** | 使用已核实地方政策，输入低于下限、处于区间内、超过上限的社保基数                   | 各险种基数按相应上下限处理；个人与企业侧金额分别正确                                        |
| **TP-10** | 工作城市和参保城市不同；修改入职年度或覆盖参保城市                                 | 查询所选参保城市／年度的政策；来源和适用年份同步变化；无匹配政策不静默继承旧城结果          |
| **TP-11** | 所选地区／年度的政策缺失                                                           | 显示警告，启用明确的全国通用**样例**回退，并将整体结果标记为低置信度，绝不以无说明的 0 替代 |
| **TP-12** | 同一已核实年度税务夹具分别选择年终奖单独计税与并入综合所得；修改租房扣除资格或金额 | 两种方案分别计算并显示差额／适用条件；默认口径可辨，扣除默认假设不冒充已确认资格            |

### 4.4 补贴、结果口径与比较

| 编号      | 前置条件／操作                                             | 预期行为                                                                                        |
| --------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **TP-13** | 添加现金补贴、报销、实物福利与条件性补贴                   | 不同发放形式和期次的现金流归集符合确认规则；税务来源及用户覆盖有效                              |
| **TP-15** | 已知税后现金、现金生活成本、个人公积金及医保个账，逐项变动 | 现金储蓄＝税后现金−现金生活成本；含权益储蓄＝现金储蓄＋个人公积金入账；医保个账与企业缴费不混入 |
| **TP-16** | 工作区中放入两份不同量纲和方向的可比指标，调整比较权重     | 按同一归一化／方向规则排序；权重变化按预期更新；不将缺失值当作有利的零值                        |
| **TP-17** | 正式 Offer 与未提交改动并存（若当期提供草稿编辑）          | MVP 的正式比较默认使用正式值；状态、数据口径和来源说明清楚，草稿不会隐式影响其他工作区          |

### 4.5 XLSX 全量数据交换

| 编号      | 前置条件／操作                                                           | 预期行为                                                                     |
| --------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| **TP-18** | 导出含多个正式 Offer 与工作区引用的数据后，在同版本空环境导入            | 文件含元信息与所需工作表；导入后关键字段、Offer ID、工作区关联和状态保持一致 |
| **TP-19** | 导入缺字段、类型错误、重复 ID、无效引用或不兼容 `schemaVersion` 的工作簿 | 阻止非法写入，错误指向适当工作表／记录并给出可理解的说明                     |
| **TP-20** | 导入与本地记录 ID 冲突的有效文件，在确认界面选择取消                     | 先看到冲突预览；取消后本地数据未改变；不能静默覆盖                           |
| **TP-21** | 在确认导入后模拟解析或写入异常                                           | 显示失败并保留可恢复的原本地数据；不能报告导入成功却仅写入部分关联对象       |

下列用例在相应 PRD 需求被排入迭代后启用，避免把后续功能误纳入 MVP 回归门槛。其中 TP-08 和 TP-14 保留原用例编号，便于后续追踪。

| 对应需求                  | 专项验证重点                                                                                                                                                                       |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PRD-F01 草稿与撤销        | 每份 Offer 仅一份编辑草稿；多份快速估算批量转正；草稿多选预览只在当前工作区；批量保存成功清理、失败保留；「稍后继续」与「放弃修改」语义区分；撤销放弃恢复原状态；50 步会话撤销上限 |

| PRD-F03 情景与展望        | 覆盖参数与继承参数的更新行为；锁定与解锁；三档区间不被解释为概率；预测可编辑假设与误差提示                                                                                         |

| PRD-M05／待排期非现金福利 | **TP-14**：公司宿舍／包食宿抵减对应生活成本，不重复增加现金收入                                                                                                                    |
| PRD-F05 扩展交换与政策    | 扩展险种的个人／企业比例、政府补贴资格；JSON 全量备份恢复；后续 CSV 结果报表语义与 XLSX 快照不同                                                                                   |

## 6. 测试数据、边界与风险

### 6.1 测试数据准备

- **金标准政策夹具**：选取明确地区、年度、险种比例、基数上下限、税率来源的官方政策样本；保留来源与核验日期。样例回退单独建夹具，不能用于证明地方政策计算准确。
- **奖金边界夹具**：覆盖金额为 0、阶梯分界点前／等于／后、不同发薪月数、绩效系数、一次性收入与总包对账差异。
- **不确定性夹具**：同一数字分别标记为用户确认、政策默认、系统估算、未知；覆盖未填值和用户明确填 0 的区别。
- **工作区与交换夹具**：多 Offer 引用、重复 ID、断裂引用、不同 schema 版本、空表与部分缺失表。
- **显示夹具**：税后现金、个人公积金、医保个账、企业缴费彼此独立；样例低置信度、政策年度和草稿状态可被用户识别。

### 6.2 高风险回归顺序

1. **P0：财务误算风险**——总包重复、奖金边界、错误税率年度、个人／企业缴费混淆、双储蓄口径错误。
2. **P0：数据安全风险**——正式保存或导入意外覆盖、失败后草稿丢失、XLSX 导入破坏引用。
3. **P0：误导风险**——缺失政策却显示精确结论、政策样例冒充官方适用值、未知数据被默认当作 0。
4. **P1：决策体验风险**——权重和排序解释不清、默认假设无法查看、移动端无法完成关键流程。

P0/P1 为本测试计划的**缺陷风险等级**，与原交接文档曾使用的需求决策优先级无关。

## 7. 环境、执行与发布门槛

### 7.1 已知运行方式与限制

原测试计划给出的现有先例为 `src/core/engine/__tests__/engine.test.ts`（Vitest），命令为：

```bash
npm test
```

按原文，当前命令在 Node 环境中运行 `src/**/*.test.ts`，**没有 DOM API**；`AGENTS.md` 中另有环境注意事项。本次没有仓库附件，未验证测试脚本、文件是否仍存在或是否已配置 IndexedDB／DOM 测试环境。因此：

- 可在现有 Node 测试环境优先验证纯计算函数。
- IndexedDB 仓储测试需明确模拟／隔离存储环境，不能在没有实现支持的情况下假定 Node 自带 IndexedDB。
- UI／端到端用例需另行选择可运行的浏览器测试环境；不要将 `npm test` 成功误认为 UI 已全覆盖。

### 7.2 建议的 MVP 发布门槛

- 第 4 节已纳入本轮交付的高风险用例全部通过；任何无法执行的场景须明确记录原因与风险，而不是记为通过。
- 计算结果与**独立核验**的政策及人工预期一致；缺失政策、已确认事实与系统估算等状态说明正确。
- 导入、导出和正式数据保存不存在已知的数据损坏／无提示覆盖缺陷。
- 核心流程在桌面和移动端都可完成；页面警示和来源解释可见、可理解。
- 测试记录应包含运行环境、代码版本、政策数据版本、夹具来源、结果及未覆盖范围。

这些是**验收建议与执行标准**，不是本次已跑通测试或已经上线的声明。
