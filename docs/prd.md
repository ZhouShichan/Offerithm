# PRD｜Offerithm（薪筹）— 国内校招 Offer 薪酬与生活质量分析平台

> **文档版本**：v0.1.0 · **更新日期**：2026-10-16 · **文档状态**：产品需求基线（不代表功能均已实现）
> **文档职责**：定义用户问题、产品行为、计算与展示口径、交付范围及产品约束；不规定代码架构或测试实现。
> **关联文档**：[技术设计](./tech-design.md) · [测试计划](./test-plan.md)

## 1. 产品概述

### 1.1 用户问题

中国大陆应届生、校招生在比较多个 Offer 时，常常面对不可直接对比的信息：基础工资、绩效和阶梯奖金等薪资结构；随地区、年度与个人条件变化的社保公积金政策；现金、报销与实物福利；居住成本、工作强度和地理成本。仅比较「年薪总包」容易遗漏成本和不确定性；自行使用表格计算又容易混淆收入、权益及假设。

### 1.2 目标用户与使用场景

- **首次比较 Offer 的应届生**：以极少输入快速判断税后现金和潜在储蓄，不必先掌握个税、社保细则。
- **持有多份 Offer 的候选人**：将不同城市、薪资结构和生活方式转为可比较的统一口径。
- **需要核实报价信息的候选人**：识别假设、政策缺口与可能改变结论的关键未知项。

### 1.3 产品定位与原则

Offerithm 是**本地优先、无需注册的 Web 应用**。其核心价值不是替用户宣布「最佳 Offer」，而是提供可解释、可质疑、可调整的分析结果。

1. **先出结果，再补细节**：快速估算只要求工作城市、企业类型和薪资表达方式及金额；复杂输入逐步展开。
2. **口径分离**：税后可用现金、住房公积金等权益、企业用人成本及现金储蓄分别展示，不混为「到手」。
3. **来源可追溯**：用户确认值、政策默认值、系统估算和未知值必须区分；缺失政策不得静默当作零。
4. **事实与假设分离**：正式 Offer、未保存修改、模拟情景不是同一种对象；假设推演不代表确定事实或概率预测。
5. **数据由用户掌控**：默认保存在浏览器本地；提供可迁移的数据导入、导出途径，并说明本地数据可能丢失的风险。

## 2. 范围与交付阶段

### 2.1 MVP（已明确纳入）

MVP 的产品闭环为：**快速估算 → 保存为 Offer → 简版多 Offer 比较 → Excel 数据导入/导出**。

| 功能域     | MVP 交付边界                                                               |
| ---------- | -------------------------------------------------------------------------- |
| 快速估算   | 工作城市、企业类型、薪资三类必填信息；可见默认假设；展示税后现金与储蓄估算 |
| Offer 录入 | 保存为正式 Offer；支持核心薪资结构、社保公积金、补贴录入                   |
| 计算结果   | 年度税后现金、现金储蓄、含权益储蓄；区分个人与企业缴费及非现金权益         |
| 简版比较   | 在工作区比较多份正式 Offer；支持基础加权排序，默认按现金储蓄口径排序       |
| 数据交换   | 一个 XLSX 多工作表文件表示全量数据；支持导出、导入、冲突预览与确认         |

MVP 的核心规则仍须满足第 4 节，包括总包防重复、未知政策显式警示和来源标记。**功能被纳入 MVP，不等于现有代码已实现。**

### 2.2 已确认、但明确不纳入 MVP

下列能力方向已确认，但本轮不作为 MVP 验收条件：

- 可保存的模拟情景 `Scenario`，以及保守／基准／乐观三档情景与区间分析。
- 3 年／10 年收入与积累预测、帕累托关系、敏感度分析与排名稳定性分析。
- 全局偏好模板的版本化、同步提示、差异预览、软删除与彻底删除流程。
- 按城市与资格条件管理的政府补贴条目。
- CSV 导出；MVP 的主数据交换格式为 XLSX。

### 2.3 已确认方向、但未单独锁定交付批次

原始需求记录还确认了以下产品行为，但现有材料未逐项说明其是否随 MVP 一同交付。**不得仅因写在 PRD 中就将其视为 MVP 承诺**：

- 多份快速估算草稿切换与批量转正；正式 Offer 编辑草稿的多份预览、批量保存和撤销放弃。
- 详细的工作强度、出差、通勤、返乡成本与有效时薪分析。
- 更完整的仪表盘、信息补全建议、可复制的 HR／学长学姐提问清单。
- 一次性收入、扩展险种与福利、企业宿舍和包食宿等完整边界能力。
- JSON 全量备份／恢复（已确认保留此通道，是否随 MVP 发布未单独锁定）。
- 单页面会话内最多 50 次按用户动作计的撤销／重做。

这些需求的行为约束见第 5 节；交付排期仍须在开发计划中明确。文中「首版」指**相应功能第一次推出时的行为边界**，不自动等同于 MVP。

## 3. 关键概念与统一口径

| 概念                                     | 产品定义                                                                                      |
| ---------------------------------------- | --------------------------------------------------------------------------------------------- |
| **快速估算草稿**（`QuickEstimateDraft`） | 尚未转换为正式 Offer 的临时试算记录；不能自动被当作正式事实                                   |
| **正式 Offer**（`Offer`）                | 用户显式保存的事实记录；同一 Offer 可被多个工作区引用                                         |
| **编辑草稿**（`OfferDraft`）             | 对既有正式 Offer 的未保存修改；不会自动覆盖正式数据                                           |
| **工作区**（`Workspace`）                | 对若干正式 Offer 的一次比较决策；可有独立比较偏好和草稿预览选择                               |
| **模拟情景**（`Scenario`）               | 对正式事实施加假设的推演对象；不回写 Offer（非 MVP）                                          |
| **字段来源**（`Provenance`）             | `confirmed` 用户已确认；`policy-default` 政策默认；`system-estimate` 系统估算；`unknown` 未知 |
| **对象状态**                             | 正式、未保存草稿、模拟情景等对象属性；**不是**字段来源的第五个值                              |
| **现金储蓄**                             | 年度税后可用现金 − 年度现金生活成本                                                           |
| **含权益储蓄**                           | 现金储蓄 + 个人住房公积金入账；医保个人账户不计入该指标                                       |

凡展示估算值，须能识别其**数据口径、默认假设、适用地区／年度、来源及不确定性**。若缺少关键数据，应显示缺失或估算标记，不得用未经说明的 0 代替。

## 4. MVP 产品需求

### PRD-M01｜快速估算

**目标**：用户无需注册，尽快获得可理解的首次估算。

- 新用户进入快速估算入口，不经过注册流程；首次使用目标为约 30 秒完成基础输入并看到结果。
- 基础输入包括：**工作城市、企业类型、薪资**。薪资允许按「年薪总包」「月薪 × 发薪月数」「自定义结构」表达；不强制先拆解总包。
- 企业类型仅为快捷参数预设（私企／央国企），**不得**替代按地区、年度与参保条件适用的法定规则。
- 使用默认假设时，结果旁必须标明默认项，生活成本样例可由用户修改；未知信息不能伪装成用户确认值。
- 估算结果至少包含年度税后可用现金与两种储蓄口径，并说明估算不等于工资承诺。

**验收要点**：三类基础输入可产生带来源说明的结果；切换薪资表达方式不会无提示重复累计收入；缺失政策有明显提示。

### PRD-M02｜保存为 Offer 与基本工作区

**目标**：把临时试算转为可复用的正式比较对象。

- 用户显式执行「保存为 Offer」才创建正式 Offer；未保存的估算不自动转正。
- 首次保存正式 Offer 时，自动建立默认比较工作区；正式 Offer 使用全局唯一身份，可被多个工作区引用。
- 工作区至少能选择多份正式 Offer 比较；不得将未保存草稿默认为正式版本。
- 正式数据的更改必须有明确保存动作；失败时不应误报成功或丢失仍可恢复的编辑内容。

**验收要点**：保存后能在工作区找到相同 Offer；比较时能区分正式数据与未经提交的修改。

### PRD-M03｜薪资组成与总包对账

**目标**：既支持快速输入，又防止重复计算。

- 支持基础固定工资、职级工资、绩效工资、考核奖励、年终奖等核心组成部分。签字费、安家费等一次性收入的完整录入批次待定；交付时须与常规收入分开标注。
- 相应奖金规则第一次交付时支持三类：**固定金额、绩效系数 × 基数、阶梯规则**（分档累进／分档区间）。互斥关系、触发门槛、层级及叠加规则是后续扩展，不视为当前三类规则的必备能力。
- 「年薪总包」是对账基准，不与明细自动相加；若明细合计与总包不一致，显示差额及警告，由用户选择以总包或明细为准。
- 年终奖的确定值、区间、按月折算及绩效依赖等不确定性应在录入和结果中明确标注；应税属性不能凭字段名称未经核实地固化。

**验收要点**：同一笔收入不会因同时填写总包和明细而计入两次；奖金规则与警告对用户可见。

### PRD-M04｜社保公积金与个税

**目标**：以可核实政策和清晰假设支持年度税后估算。

- 以**参保城市 + 适用年度**选取政策；参保城市默认工作城市、允许手动修改，年度默认入职年度。
- 展示五险一金适用项目、缴费比例与基数上下限；允许逐项启用／停用并在高级配置中修改基数和比例。扩展险种和企业福利按适用情况记录，不推定所有用户都有「七险二金」。
- 将个人缴费、企业缴费分别列示；企业缴费不作为员工税后现金。
- 政策数据必须包含可核实的地区、年度、适用条件和来源。地区政策缺失时，提示缺失，并以**明确标注为样例的全国通用配置**估算；结果整体标为低置信度，不静默填 0。
- 个税主要按**年度汇算口径**展示；年终奖「单独计税」和「并入综合所得」两种结果并列，列出差额及适用条件，默认展示口径为单独计税，但不宣称该方式对所有人都最优。
- 专项附加扣除的已确认产品默认方案为：仅预填住房租金扣除并按城市档位给出参考值（直辖市／省会 1,500 元／月；市辖区户籍人口超过 100 万 1,100 元／月；其余 800 元／月），其他专项附加扣除默认 0、可补充。**预填值是需核实资格与政策年度的默认假设，不代表用户自动符合扣除条件。**

**验收要点**：年度税额和缴费构成可解释；修改城市、年度或基数会重算；政策缺失时有可识别的回退与低置信度标记。

### PRD-M05｜补贴、生活成本与储蓄口径

**目标**：把可支配现金与非现金权益分开估算。

- 支持录入现金、报销、实物及附带条件的补贴，标注按月／按年／按资格／按事件发放；核心企业补贴属于 MVP，**政府补贴条目不纳入 MVP**。
- 补贴的应税判断可提供类型驱动默认建议，必须注明是政策默认还是系统估算，并允许用户依据实际文件更正；不能把示例税务归类直接当成普适法规。
- 公司宿舍、包食宿等非现金福利的完整录入批次待定；交付时应体现为相应生活成本的抵减，不得同时作为现金补贴重复入账。
- 可编辑住房、餐饮、交通等年度生活成本；城市档位可以提供明示为「系统估算」的样例。
- 并列展示**年度税后可用现金、现金储蓄、含权益储蓄**。个人公积金入账只增加含权益储蓄；医保个人账户单独列示，不并入这两种现金口径。企业总用人成本如提供，须另列、不混入个人现金；该扩展指标的交付批次未单独锁定。

**验收要点**：现金和权益不会被混加；修改生活成本会影响储蓄；非现金福利不会重复增加现金收入。

### PRD-M06｜简版 Offer 比较

**目标**：让多份 Offer 在统一口径下可比较。

- 工作区对多份**正式 Offer**呈现税后现金、两种储蓄指标及主要收入／支出构成。
- 支持自定义基础指标权重和加权排序；默认比较储蓄时使用**现金储蓄**，同时显示含权益储蓄供参考。
- 排序须说明指标口径与权重，不将信息完整度误表示为 Offer 本身的优劣，也不宣称加权第一名就是客观最优。
- 帕累托、敏感度、排名稳定性和高级情景比较属于后续能力，不作为本条 MVP 验收条件。

**验收要点**：权重改变时结果按相同规则更新；每份 Offer 的正式状态及计算口径可辨认。

### PRD-M07｜Excel 数据导入与导出

**目标**：提供面向非技术用户、可恢复的本地数据交换。

- 以单个 **XLSX 多工作表**文件承载本地数据库全量数据，按领域对象分表，并包含元信息表（至少记录 `schemaVersion`、导出时间、数据状态及口径说明）。尚未推出的对象类型可保留兼容性设计，不能据此宣称相应功能已上线。
- 导入前检查数据与冲突，展示冲突预览，用户再次确认后才应用；错误须能定位到对应数据，不能静默覆盖。
- 导出时说明快照包含的数据对象及正式／草稿状态；**XLSX 全量交换**不等同于未来单独的「比较报表 CSV 导出」。
- 已确认另保留 JSON 全量备份／恢复通道，作为机器友好的补充；其发布批次尚未独立明确。

**验收要点**：同版本数据导出后可重新导入并恢复主要领域对象及关联；冲突未确认不得覆盖本地数据。

## 5. 后续与待排期需求的已确认行为

以下为**产品规则存档**，并非 MVP 验收清单；实施时须按第 2 节确定批次。

### PRD-F01｜草稿、预览与撤销（排期待定）

- `QuickEstimateDraft` 支持自动保留、新建多份、切换和仅在快速估算上下文中比较；支持多选批量「保存为 Offer」，保存前列出清单，保存后加入当前工作区。首版不提供批量转正的工作区选择器。
- `OfferDraft` 对同一正式 Offer **最多一份**。编辑实时更新预览并自动持久化草稿，只有显式保存才更新正式 Offer；保存成功清理对应草稿并退出其预览，保存失败保留草稿。
- 默认展示正式数据；如有未完成草稿，提供**非阻断**的恢复、预览、丢弃入口。每个工作区独立决定预览哪些 Offer 草稿，允许多个同时预览；切换到别的工作区时只使用正式 Offer 数据。
- 「稍后继续」保留草稿、退出预览；「放弃修改」删除草稿，采用立即删除加短暂撤销入口。撤销必须恢复草稿内容及原编辑／预览状态。批量放弃等高风险操作另做二次确认。
- 当前页面会话可按用户动作撤销／重做，最多 50 步；该历史不等同于正式数据版本或永久操作日志。

### PRD-F02｜偏好模板与同步（明确不在 MVP）

- 全局允许多套比较偏好；工作区引用模板 ID 与版本，同时维护可独立调整的本地快照。本地修改不反写全局模板。
- 模板有新版本时可预览差异并手动「整套替换为全局新版」或「保留本地快照」；首版**不做字段级冲突合并**。
- 「暂不同步」抑制当前版本重复提醒，新版本可再次提示；「不再提醒」关闭该关联的自动提示，但仍可手动检查。
- 删除模板先进入回收站；彻底删除前提示关联工作区数量并要求确认，之后断开引用而保留工作区快照与计算能力。

### PRD-F03｜情景分析与长期展望（明确不在 MVP）

- 模拟情景可命名、保存、比较、恢复，默认继承正式 Offer 最新事实；未经覆盖的参数跟随正式数据，覆盖项可锁定，且不能改写正式事实。
- 保守／基准／乐观及估算区间是**假设推演**，不解释为概率分布；敏感度、排名稳定性与帕累托关系仅辅助用户判断权衡。
- 3 年／10 年预测允许修改增长率、晋升和生活成本假设。原已确认的样例假设为年薪增长率 5%、CPI 3%、无晋升；这些是**可修改样例**，不是预测事实。预测结果应有区间与明显的误差说明。

### PRD-F04｜工作强度、地理成本与决策支持（排期待定）

- 工作时间按「上班到下班」统计，不扣午晚饭时长；允许记录出差频率、地点偏远程度、市区通勤时长以及回乡的交通方式、耗时和费用。
- 有效工时采用「年度工作日 × 每日工时 + 通勤折算」；原产品决策给出的通勤折算系数样例为 0.5，可由用户修改。展示有效时薪时应标明工时口径。
- 综合仪表盘可并列展示税后现金、储蓄、住房交通开支、权益及工作时间，支持按信息透明度、攒钱能力、工作强度等视角观察；逐步提供信息补全优先级和可复制提问清单。

### PRD-F05｜扩展政策与数据交换（按对应批次交付）

- 支持补充医疗、长期护理、补充公积金、企业年金等扩展条目，按实际资格逐项启用或关闭。
- 地方政府补贴按「城市 + 资格条件」录入，已确认**不内置完整政府补贴数据库**。
- CSV 是后续的结果导出能力；JSON 是独立的全量备份通道，均不能与 MVP 的多表 XLSX 语义混淆。

## 6. 全局体验与内容约束

- **启动逻辑**：新用户默认快速估算；有历史工作区的用户默认进入最近使用的工作区，并可切换到快速估算入口。草稿恢复提示不应阻断用户查看正式数据。
- **解释优先**：重要指标同时显示来源、地区／年度、计算口径和不确定性；默认值可以查看、修改，不宣称基于不足信息得出确定结论。
- **视觉语言**：整体参考 [cafe 设计体系](https://open-design.ai/zh/plugins/systems/) 的暖色调、柔和排版与清洁布局，配合流畅但不过度的动效；文案克制、具体，参考[去除网站 AI 味指南](https://echo-tail.github.io/Echo-Tail/2026/02/04/%E7%BD%91%E7%AB%99%E5%8E%BB%E9%99%A4AI%E5%91%B3%E7%BB%88%E6%9E%81%E6%8C%87%E5%8D%97/)避免模板化或夸张表达。
- **终端适配**：要求移动端具备完整功能，以响应式设计适配，不另建一套移动端信息架构。
- **政策可信度**：每条内置地方政策均应有官方来源链接及适用地区、年度／条件；首批以全国通用**样例**和少量有依据的城市数据为起点，未覆盖城市如实标注。
- **本地使用风险**：无账号与云备份；在导入、恢复及高风险数据操作附近提示浏览器数据清理可能造成丢失。

## 7. 不在产品目标内

- 账号系统、云同步、服务端存储、多用户实时协作。
- 跨标签页的编辑锁、租约、接管或复杂多人冲突合并。
- 将估算置信度等同于薪酬好坏，或用一个强制总分替用户做决定。
- 将情景区间当作概率预测，或把样例政策伪装为真实、适用于每人的政策值。
- 将完整政策库、长期预测模型或所有地方税收细节的实现视为本轮 PRD 已完成的技术设计。

## 8. 待设计事项与变更说明

### 8.1 已确认产品原则，仍待技术落地

- 具体薪资、扣缴与年度汇算算法、地方政策数据覆盖与更新策略的**实现与合法性核验**，由 [技术设计](./tech-design.md) 承接；PRD 不锁死代码或数据结构。
- 非 MVP 项目的细分交付批次，以及 JSON 通道、扩展福利、草稿高级操作等功能的上线时间，仍需排期决定。
- 指标归一化算法、XLSX 精确字段映射、UI 组件选型和自动化测试实现均不属于本文件的职责。

### 8.2 本版整理说明

本版保留上传资料中已确认的产品方向，并将原来混写的 MVP、后续能力和实现细节分离；不新增功能承诺。原文将「来源」与「草稿／情景状态」并列为五类、将 CSV 与 MVP Excel 混写、将所有用户故事无差别呈现为当前需求的问题，已按后续明确决策统一。历史交接文档仅作为决策背景，不凌驾于本 PRD 已整理的产品范围之上。
