# ADR 0001：以 Excel 多表工作簿作为数据导入导出格式

- 状态：已接受（2026-10-15）
- 决策人：产品负责人

## 背景

Offerithm 是本地优先应用，数据全部存于浏览器 IndexedDB。用户需要导出比较结果、全量备份，以及让非技术用户（应届生用户群）能够离线完整录入/修改自己的全部信息再导入。

## 决策

以一个 XLSX 工作簿表示整个数据库：每个领域对象一张工作表（Offer / Draft / Workspace / PreferenceProfile / Scenario / Settings 等），另设一张元信息表（schemaVersion、导出时间、数据状态、口径说明）。导出即全量备份；导入支持完整信息录入，导入前展示冲突预览并二次确认。JSON 全量导出/导入保留为机器级备份通道，人机交互主通道为 Excel。

## 理由

- 目标用户（应届生）普遍熟悉 Excel，多表结构可承载嵌套的薪资结构、险种、补贴等完整信息，CSV 单表无法表达。
- "工作簿 = 数据库"让备份文件本身可读、可手工编辑，降低非技术用户的心理与操作门槛。

## 后果

- 需要引入 XLSX 读写库（如 exceljs / sheetjs）并维护"工作表 ↔ 领域对象"的双向映射与 schema 校验，映射代码随领域类型演进需同步维护。
- Excel 单元格类型弱（数字/日期/文本易漂移），导入必须做严格校验与错误定位提示。
- 嵌套结构（如奖金规则数组）在二维表中需约定展开编码，schemaVersion 表是兼容性关键。
- JSON 通道的存在意味着两套序列化格式需保持语义一致，测试面扩大。
