# 政策数据(Policy Data)

Offerithm 的全部政策参数（税率表、社保/公积金费率、缴费基数上下限）只存在于本目录；计算引擎经参数接收政策对象，禁止在计算逻辑中硬编码政策数值（见根目录 `CONTRIBUTING.md`）。

- 领域契约：`src/core/types.ts` 的 `RegionPolicy` / `TaxPolicy`（本 README 不重复字段类型，以契约为准）。
- 结构决议：issue #10；数据唯一来源：`research/policy-sources` 分支 `docs/research/policy-sources.md`（下称「调研报告」）。
- 注册表入口：`src/policies/index.ts`（加载即校验 + `findRegionPolicy(region, dateISO)` / `getTaxPolicy(year)`）。

## 目录结构：一文件 = 城市 × 政策期

```
src/policies/
├── README.md                 # 本文件
├── index.ts                  # 注册表：加载 JSON + 类型守卫 + 查找
├── regions/                  # 地区政策（社保+公积金）
│   ├── national-sample.json  # 全国通用样例(回退配置)，scope: "national-sample"
│   ├── beijing-2025.json     # effectiveFrom 2025-07-01 ~ effectiveTo 2026-06-30
│   ├── beijing-2026.json     # 2026-07-01 ~ 2027-06-30
│   └── guangzhou-2025.json   # 2025-07-01 ~ 2026-06-30
└── tax/
    ├── 2025.json             # 年度税率表/速算扣除数/基本减除/租金三档
    └── 2026.json
```

- 主导体系：文件按城市主导政策周期建文件（北京＝社保年度，7 月起；广州＝社保年度主导，医保按自然年的差异写入 `medical` 条目 `note`）。同城社保年度与公积金年度错期时，同样以字段级 `note` 说明，引擎不做字段级日期切换（MVP 精度边界，#10 决议）。
- `year` 为标称年度；精确适用期以 `effectiveFrom`/`effectiveTo`（ISO 日期，含两端）为准。
- 文件可在契约字段外携带文件级 `note`（时效/适用条件声明，UI 展示用）；险种条目 `note` 记录字段级差异与时效。

## 单位与取值约定

- 费率一律小数：`0.16` = 16%，`0.098` = 9.8%；金额一律元（月度口径除非另注明）。
- 日期 ISO 8601（`YYYY-MM-DD`）。
- `personalAccount` 表示该险种缴费是否划入个人账户（医保个账、公积金为 `true`）。
- 法定五项 `pension` / `medical` / `unemployment` / `injury` / `maternity` 必填；`housingFund` 及扩展条目按政策实际启用。生育并入医保的城市，`maternity` 记 `0/0` 并在 `note` 说明已计入医疗单位费率，避免重复计缴。
- 速算扣除数(Quick Deduction)按《国家税务总局公告2018年第56号》「按月换算后的综合所得税率表」转录（0/210/1410/2660/4410/7160/15160）；年度综合所得汇算口径为其 ×12（0/2520/16920/31920/52920/85920/181920）。引擎实现须按用途取对应口径，不得混用。

## 来源要求（诚信原则，不可协商）

每个 JSON 文件必填 `source`：官方 URL（政府域名原文页或其法定载体，如市政府公报），多个来源用分号「；」分隔并注明各自对应的数值。加载期类型守卫(Type Guard)对缺 `source`、缺法定五项、缺 `effectiveFrom`/`effectiveTo`、`scope` 非法、数值字段缺失或矛盾等一律抛错。

调研报告的核实等级：

| 等级 | 含义 | 能否进种子 |
| --- | --- | --- |
| ✅ 已核实 | 数值 + 官方来源链接齐备 | 可以 |
| ⚠️ 部分核实 | 文号明确、多家转载一致，但无政府域名原文页 | 不可以，需先补官方链接 |
| ❌ 未核实 | 来源冲突或仅单一二手来源 | 不可以 |

**只有全量 ✅ 的城市才进种子。** 全国样例(national-sample)是拼装回退配置而非权威口径：其基数按「全口径平均工资 60%–300%」口径以调研报告 ✅ 锚点折算（详见该文件 `note`），命中回退时计算结果整体低置信度。

## 社区 PR 补城市流程

1. 对照下方「待补清单」与调研报告对应城市小节，逐项补齐官方原文页链接（政府域名或法定载体；转载站如 shui5.cn 不算）。
2. 新建 `regions/<城市>-<年度>.json`，按上述格式填写；`region` 用规范行政区名（如「武汉市」），查找时自动容忍「武汉」式简称。
3. 在 `index.ts` 的 `regionFileEntries` 注册文件；新增年度个税文件同理注册 `taxFileEntries`。
4. 本地通过 `npm run typecheck && npm run lint && npm test`（加载即校验会拦下坏数据）；为新增数据补抽查断言（附来源推导注释）。
5. PR 描述给出每个数值的官方来源链接（`CONTRIBUTING.md` 既有规则）；数值拿不准时写入 `note` 标注，不得伪装成确定值。

## 年度维护检查单

- 每年 6–9 月各城陆续发布新社保年度/公积金年度/自然年通告：更新或新增 `regions/*.json`，旧的保留（历史 Offer 按其入职日期命中旧期文件）。
- 《住房公积金管理条例》2026 修订（国务院令第 844 号，2026-09-20 施行）后缴存比例上限不再由条例写死 12%：各城 2027 年度通知发布后按新口径跟进（#10 决议第 4 条）。
- 阶段性降费/延续文件（失业 1%、医保降费等）到期前后核对是否延续，未检索到延续文件时在条目 `note` 注明时效，不得默认延续为确定值。
